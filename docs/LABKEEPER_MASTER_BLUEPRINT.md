# LabKeeper System Blueprint (마스터 설계도)

> **버전**: v2.0 (Physical AI 전환 개편본)  
> **목적**: 생명공학 연구실 물품 대여·재고 관리 및 지능형 자율 방범(Physical AI) 로봇 시스템의 전체 청사진.
> **문서 관계**: 이 문서는 제품 비전용 청사진이다. 현재 구현 상태와 기술 선택, 실행 순서는 `PHYSICAL_AI_EDGE_TRANSITION_PLAN.md`를 우선한다.

---

## 1. 프로젝트 비전 및 진화 방향

LabKeeper는 위험물이 많은 생물/화학 연구실의 안전과 자산을 관리하기 위해 탄생했습니다. 
기존에는 로봇이 카메라로 영상을 찍어 보내면 무거운 PC(관제 서버)가 이를 받아 AI로 분석하는 클라우드/PC 종속형 구조를 사용했습니다.

**최종 목표 아키텍처(v2.0)**의 핵심 비전은 PC 서버의 개입을 완전히 없애고, **Raspberry Pi 5 로봇 단독으로 AI 추론, 상황 판단, 주행 제어를 모두 자체적으로 처리하는 "순수 Physical AI (일체형 엣지 컴퓨팅)" 구조로 진화**하는 것입니다.

---

## 2. 전체 시스템 아키텍처 (Global Architecture)

시스템은 3개의 기둥으로 이루어져 있습니다.

1. **Physical AI 로봇 (Raspbot - Raspberry Pi 5)**
   - 현장을 순찰하며 스스로 위협을 감지하고 판단하는 독립적인 엣지(Edge) 로봇입니다.
   - 로봇 내부에 Pi 5 실측을 통과한 경량 추론 모델을 탑재하여, 통신 지연이나 외부 추론 서버 없이 객체 탐지를 수행합니다.
2. **Web Console & Digital Twin (웹 프론트엔드)**
   - 관리자가 접속하여 로봇의 시야를 실시간으로 모니터링하고, 연구실 전체를 탑다운 맵(Digital Twin)으로 조망하며 관리하는 대시보드입니다.
3. **Supabase (클라우드 백엔드)**
   - 로봇과 웹을 연결하는 데이터베이스(DB) 및 스냅샷 저장소입니다.

---

## 3. Physical AI 로봇 설계 방향

### 3.1 하드웨어 제어
- **구동계:** 4WD 스키드-스티어 방식. I2C 통신을 통해 제어.
- **센서:** 전방 초음파 센서(장애물 감지), 하단 IR 센서(라인 트래킹).
- 기존의 하드웨어 제어 인터페이스(HAL)를 유지하면서, 내장된 AI 비전 시스템과 유기적으로 결합하여 자율 주행을 수행합니다.

### 3.2 AI 비전 파이프라인 (The Brain)
- **경량화 모델 적용:** 현재 YOLO11 연구실 모델의 **NCNN 변환본을 먼저 실측**하고, 결과가 부족할 때만 다른 nano 모델을 비교합니다. 모델명보다 실제 Pi 처리량·지연·정확도를 선택 기준으로 삼습니다.
- 카메라로 들어온 실시간 영상을 로봇 내부에서 직접 분석하고, 그 결과(바운딩 박스 등)를 즉각 주행 제어와 안전 판단 로직에 반영합니다.

### 3.3 로컬 오프라인 큐
- 로봇이 음영 구역(와이파이가 끊기는 곳)에 진입하더라도, 감지된 안전 이벤트는 로컬 큐에 안전하게 저장되었다가 네트워크가 복구되면 서버로 전송됩니다.

## 4. 인공지능 안전 엔진 규칙 (Safety Rules)

AI는 단순한 객체 인식을 넘어, 연구실의 상황을 이해하고 핵심 안전 규정을 판정합니다.

| Rule ID | 위험도 | 시나리오 정의 |
|---|---|---|
| **SR-01** | `MEDIUM` | **주행 장애물 감지:** 순찰 경로상에 이동형 장애물이 있어 경로가 막힌 경우 (우회 또는 정지). |
| **SR-02** | `HIGH` | **화재 안전 설비 차단:** 소화기나 스필킷 바로 앞을 일반 박스나 장애물이 가로막고 있는 위험 상황 감지. |
| **SR-03** | `HIGH` | **야간 침입자 발생:** 방범 모드(Night Guard) 중 사람이 감지된 경우. 즉각 추적 모드로 전환하여 대상 추적. |
| **SR-04** | `HIGH` | **화학 시약 무단 방치:** 시약병이나 플라스크가 지정된 보관함 밖에서 방치된 상황 인지. |

## 5. Web Console & 디지털 트윈 (NVIDIA Isaac Sim 연동)

### 5.1 SVG 탑다운 맵 (Virtual Lab)
- NVIDIA Isaac Sim의 3D 가상 환경 좌표 데이터를 바탕으로, 실제 실험실 물리 좌표를 웹의 SVG 좌표계에 1:1로 정밀 매핑합니다.
- 로봇의 실시간 위치와 각종 기기/시약의 위치가 직관적으로 렌더링됩니다.

### 5.2 로봇 원격 콘솔 (Teleoperation)
- 로봇 내부에서 자체 AI 분석이 끝난 결과 화면을 PC(관제 서버)를 거치지 않고 웹 브라우저로 직접 송출하여 초저지연 모니터링을 구현합니다.
- 조이스틱을 통한 원격 수동 제어를 지원하며, 통신 단절 시 로봇이 자동으로 정지하는 안전장치를 포함합니다.

### 5.3 안전 이벤트 라이프사이클 관리
- 로봇이 올린 위반/경고 이벤트는 관리자의 검토(`NEEDS_REVIEW`)와 조치(`ACTION_TAKEN`)를 거쳐 최종 종료(`CLOSED`)되는 프로세스를 따릅니다.

---

## 6. 마이그레이션 전략 (개발 방향성)

- **AI 엔진의 완전한 독립:** PC에 의존하던 분석 코드를 로봇 내부로 통합합니다.
- **적정 기술 선택:** 라즈베리파이 5에서 NCNN 후보를 측정하고, 제어 루프와 추론 루프를 분리하며 최신 프레임만 처리합니다. 모델 교체는 측정 결과가 필요할 때 진행합니다.
- **단일 기기 자율성 확보:** 외부 관제 스크립트를 모두 걷어내고, 라즈베리파이 전원만 켜면 모든 AI와 주행이 완벽히 작동하는 시스템을 완성합니다.
