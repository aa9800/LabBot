가상 로봇 시뮬레이터 배우기

실제 Raspbot이 오기 전에, 화면 속 가상 로봇으로 라인트래킹·장애물회피·QR스캔·실사를 미리 연습합니다. 순서대로 따라오시면 됩니다.

0 이게 뭘 하는 건가요

실제 로봇이 하게 될 "판단"(라인 따라가기, 장애물 만나면 정지, 선반 앞에서 물품 확인)을 화면 위 가상 로봇으로 미리 만들고 테스트하는 프로그램입니다. 여기서 검증한 로직은 나중에 실제 로봇에 거의 그대로 옮겨집니다 — 그래서 지금 이 안에서 확실히 이해하고 넘어가는 게 중요해요.

1 준비물 확인

확인명령
Python 설치돼 있는지python --version (3.10 이상이면 OK)
최신 코드 받기git pull (LabKeeper 폴더에서)

2 설치 & 실행

cd robot-sim
pip install -r requirements.txt
python main.py

창이 뜨고 주황색 점(로봇)이 회색 선을 따라 스스로 움직이면 성공입니다.

웹까지 같이 보고 싶다면 robot-sim/.env에 Supabase 접속정보를 채워두면(.env.example 참고), 로봇이 장애물을 감지했을 때 실제 웹(Supabase) Safety 화면에 이벤트가 뜨는 걸 볼 수 있습니다. 로컬 웹서버를 따로 켤 필요는 없습니다(2026-08-25부터 pygame도 Webots처럼 Supabase에 직접 연결). .env가 없어도 로봇 자체는 정상 동작합니다.

3 화면에 보이는 것 이해하기

회색 선 — 로봇이 따라가는 경로 (실제 라인트래킹 센서가 인식하는 검은 선)
주황 점 — 로봇 (앞쪽으로 향한 짧은 선 = 로봇이 보는 방향)
청록 원 — 체크포인트(선반). 옆 숫자는 그 선반에 지금 남아있는 물품 수
주황 사각형 — 장애물

왼쪽 위에 계속 올라오는 글자들은 "방금 무슨 일이 있었는지" 로그입니다 — QR 스캔, 장애물 감지, 실사 제출 결과 등.

4 조작해보기

키동작확인할 것
SPACE로봇 앞에 장애물 놓기로봇이 멈추는지, 로그에 "장애물 감지" 뜨는지
C장애물 전체 치우기로봇이 다시 움직이기 시작하는지
M무작위 물품 하나를 선반에서 몰래 없앰그 선반 숫자가 줄어드는지
F지금까지 스캔한 결과를 실사로 제출로그에 "불일치 N건" 뜨는지 (몰래 없앤 물품이 잡히는지)
N스캔 기록 초기화새로 순찰 한 바퀴 시작할 때 사용
R로봇 위치 리셋처음 자리로 돌아감
ESC종료

추천 순서: 그냥 한 바퀴 돌게 지켜보기 → M으로 물품 하나 없애기 → 로봇이 그 자리를 다시 지나가게 두기 → F로 제출해서 정확히 잡히는지 확인.

5 창 없이 로직만 빠르게 확인 (연습)

매번 창을 띄우지 않고 로직만 빠르게 돌려보는 방법도 있습니다.

python check_logic.py

2000틱을 순식간에 돌리고 마지막 위치·로그를 출력합니다. 코드를 조금 고쳤을 때 "안 깨졌는지"만 빠르게 확인하고 싶을 때 씁니다.

6 코드 한 줄 씩 바꿔보며 감 잡기

  1. 1
    controller.py의 SPEED 값을 70에서 30으로 바꾸고 다시 실행 — 로봇이 얼마나 느려지는지 체감
  2. 2
    sim/engine.py의 TRACK_POINTS 좌표를 살짝 바꿔서 경로 모양이 어떻게 바뀌는지 확인
  3. 3
    controller.py의 OBSTACLE_STOP_DISTANCE를 40에서 80으로 늘려서, 로봇이 더 멀리서부터 멈추는지 확인

이런 식으로 값 하나씩 바꿔보면서 "이 숫자가 뭘 담당하는지" 감을 잡는 게, 실제 로봇 왔을 때 값을 튜닝하는 데 그대로 도움이 됩니다.

7 코드가 어떻게 나뉘어 있는지

파일역할
controller.py판단 로직만. "센서가 이렇게 읽히면 이렇게 움직인다" — 실제 로봇에도 그대로 재사용될 부분
sim/engine.py가상 세계 자체 (트랙, 물리, 그리기)
sim/hal_sim.pycontroller.py가 센서값을 "물어보는" 창구 — 지금은 가상 세계에 물어봄
real_hal.py실제 로봇 오면 채울 자리. 지금은 비어있음(TODO)
notify_supabase.py웹(Supabase)으로 이벤트/물품목록 전송·조회 — pygame과 Webots가 공용으로 씀(2026-08-25부터 통일)
main.py창 띄우고 키 입력 처리, 위 조각들을 연결
왜 이렇게 나눠놨나 controller.py는 가상 세계인지 실물인지 전혀 모릅니다 — hal_sim.py/real_hal.py 중 뭘 연결하느냐만 다릅니다. 그래서 지금 시뮬레이터에서 검증한 판단 로직이, 실제 로봇 왔을 때 real_hal.py만 채우면 그대로 옮겨갑니다.

8 실제 로봇이 왔을 때 할 일 (미리보기)

real_hal.py를 열어보면 5개 메서드가 TODO로 비어있습니다. Yahboom이 제공하는 예제 코드를 참고해서 이 5개만 채우면 됩니다 — controller.py는 손댈 필요 없습니다.

9 Webots — 주 개발·발표용 3D 연구실

pygame은 화면 시연이 아니라 로직을 빠르게 확인하는 내부 테스트용입니다. 실제 개발과 발표는 9개 보관구역과 대표 장비가 배치된 Webots 연구실에서 진행합니다. controller.py의 HAL 구조는 그대로 재사용합니다.

먼저 확인 Webots는 이 저장소의 pip install로 안 깔립니다 — 별도 프로그램(cyberbotics.com)이라 미리 설치돼 있어야 합니다. 설치됐는지 모르겠으면 시작 메뉴에서 "Webots" 검색.

실행 방법

  1. 1
    Webots 실행 → 메뉴 File > Open World... → robot-sim/webots_project/worlds/lab.wbt 선택
  2. 2
    화면 위쪽 툴바의 ▶(재생) 버튼을 누른다 — Webots는 항상 일시정지 상태로 시작해서, 안 누르면 로봇이 안 움직인다
  3. 3
    로봇이 검은 선을 따라 사각 루프를 스스로 돌면 성공

화면에 보이는 것

바닥의 검은 선 — 트랙(순찰 경로), pygame의 회색 선과 같은 역할
청록색 원 — 체크포인트. 웹 DB에 등록된 실제 물품 위치를 기준으로 로봇이 실행할 때마다 자동으로 만든다(아래 "웹 연동" 참고)
주황색 박스 — 장애물(OBSTACLE_1)
로봇 — E-puck 차동구동 물리 위에 Raspbot형 직사각 차체와 전면 카메라 외형을 얹은 시각 프록시. 실제 치수는 실기기 확인 후 보정

콘솔 로그 읽는 법

창 아래쪽 Console 패널에 뜨는 문구들:

로그의미
웹 DB에서 위치 N곳을 체크포인트로 불러왔습니다시작할 때 웹의 물품 위치를 성공적으로 가져옴
체크포인트 확인: 기기실-1그 위치(체크포인트)에 도착해서 잠깐 정지·확인함
장애물 감지(39.8cm) — 정지 + SR-01 안전이벤트 전송40cm 이내로 접근 → 정지 + 웹 Safety에 이벤트 전송

모드 전환: 수동조작 / 자동순찰웹의 Robot Console에서 원격조작 모드를 켜거나 껐을 때

장애물 직접 다뤄보기

왼쪽 트리(Scene Tree)에서 DEF OBSTACLE_1 Solid 항목을 글자 자체를 클릭해서 선택 → 3D 화면에 뜨는 기즈모로 옮기거나, Delete로 지워본다. 지워도 로봇이 다시 움직이기 시작하는지 확인. (3D 화면에서 직접 클릭하면 로봇 몸체를 잘못 선택하기 쉬우니, 왼쪽 트리에서 이름으로 고르는 게 정확하다.)

월드를 다시 불러올 때 — Save 아니고 Discard 코드를 고쳐서 월드를 다시 열어야 할 때(Ctrl+Shift+R) "저장할까요?" 팝업이 뜨면 반드시 "Discard"를 눌러야 한다. "Save"를 누르면 지금 화면에 떠 있는(직접 옮기거나 지운) 상태가 파일에 덮어써져서, 코드로 고친 최신 내용이 사라져버린다.

웹 연동 — 체크포인트와 안전이벤트

Webots를 실행하기 전에 웹을 먼저 켜두면(labkeeper-web-local 서버, 또는 Supabase 기반 web/), 로봇이:

  • 시작할 때 웹의 실제 물품 위치(기기실-1, 세포배양실 등)를 가져와서 그 개수만큼 체크포인트를 자동으로 만든다(robot-sim/webots_project/controllers/labkeeper_controller/labkeeper_controller.py의 _build_checkpoints_from_items)
  • 장애물을 감지하면 SR-01 안전이벤트를 실제로 웹 DB에 전송한다 — 관리자 페이지(admin.html) 로그인 후 "안전 이벤트" 탭에서 확인 가능

이 연동은 robot-sim/notify_supabase.py가 담당하고, robot-sim/.env(git에는 안 올라가는 파일)에 Supabase 접속정보가 있어야 동작한다. 없으면 콘솔에 안내 메시지가 뜨고, 체크포인트는 웹과 동일한 9개 연구실 위치 고정값으로 대체된다 — 그래도 로봇 자체는 정상 동작한다.

Robot Console — 웹에서 카메라 보고 직접 조작하기

관리자 페이지 → "안전 이벤트" 탭 맨 위에 Robot Console이 있다.

  • 카메라 화면: 실시간 영상이 아니라 몇 초 간격 스냅샷(로봇이 주기적으로 사진을 찍어 업로드함)
  • ▲▼◀▶ / ■ 정지 버튼: 누르면 그 즉시 로봇이 자동순찰을 멈추고 그 명령대로 움직인다("수동조작" 모드로 전환)
  • "자동 순찰로 복귀": 다시 자동 모드로 돌려놓는다
  • 안전정지는 원격조작 중에도 그대로 적용 — 수동조작 중이라도 40cm 이내에 장애물이 있으면 로봇이 스스로 멈춘다. 이 정지는 웹에서 풀 수 없다(현장에서 직접 확인 필요) — 실수로 장애물 쪽으로 계속 밀어붙이는 걸 막기 위한 설계다

10 Isaac Sim — 지금은 설치만 (발표 이후용)

월요일 발표에는 필요 없습니다. Webots + pygame만으로 발표가 완결됩니다. Isaac Sim은 발표 이후 "더 정밀한 물리 + 강화학습" 단계에서 쓸 도구라, 지금은 설치만 미리 해뒀습니다.

왜 따로 필요한가

Webots는 가볍고 빠르게 로직을 검증하기 좋고, Isaac Sim(NVIDIA)은 훨씬 정밀한 물리 시뮬레이션과 GPU 기반 대규모 강화학습에 특화돼 있습니다. 지금 단계(순찰 로직 검증)에는 Webots가 충분하고 훨씬 간단해서, Isaac Sim은 나중에 "라인트래킹을 스스로 학습시키기" 같은 단계에서 쓰게 됩니다.

설치 확인

Isaac Sim은 일반 파이썬이 아니라 전용 가상환경(Python 3.12)에 따로 설치돼 있습니다 — 지금 쓰는 로봇시뮬 코드와 완전히 분리돼 있어서 서로 영향 없습니다.

cd isaac-sim-env
venv\Scripts\python.exe -m pip show isaacsim

버전 정보가 뜨면 정상 설치된 상태입니다.
