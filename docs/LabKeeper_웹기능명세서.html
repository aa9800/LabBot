LabKeeper Web

실습실 물품 대여·재고관리 웹의 화면·필드·처리 로직을 실제 구현 기준으로 정리한 문서. 로봇·아두이노는 다루지 않는다.

범위웹 전용 (1주차 MVP)

위치LabKeeper/web
01 개요 및 범위

이 문서가 다루는 것

LabKeeper 웹은 실습실 물품의 등록·검색·대여·반납·재고실사·통계를 처리하는 서비스다. 이 문서는 실제로 구현된 웹 애플리케이션(LabKeeper/web)의 화면 구성과 각 기능의 세부 로직을 설명한다. 로봇(Raspbot)·아두이노 게이트 연동은 다음 단계 범위이며 여기서는 다루지 않는다 — 관련 내용은 기술 설계 문서를 참고한다.

지금 상태로도 사람이 모든 화면을 직접 조작해 실습실을 운영할 수 있도록, 로봇 유무와 무관하게 독립적으로 완결되게 만들었다.

04 물품 관리

목록 · 검색 · 등록 · 상세

4.1 목록 / 검색 (/items)

세 조건은 AND로 결합되며, 비워두면 해당 조건은 무시된다.

q
이름 부분일치 검색
category
카테고리 정확히 일치
location
위치 정확히 일치

결과는 이름 오름차순으로 정렬되며, 재고(available_qty)가 0이면 "전량대여중" 표시가 붙는다.

4.2 등록 (/items/new)

필드필수설명
name예물품명, 자유 텍스트
category예자유 텍스트 입력 (사전 정의된 목록 없음)
location예위치 코드, 자유 텍스트 (예: A-1)
total_qty아니오 (기본 1)등록 수량 = 초기 available_qty

등록을 누르면 서버가 8자리 임의 코드(secrets.token_hex(4))를 qr_code로 발급하고, 그 코드를 인코딩한 QR PNG를 자동 생성해 물품 상세 페이지로 이동한다.

4.3 상세 (/items/{id})

QR 이미지·코드, 카테고리/위치/재고/상태, 그리고 재고가 있을 때만 대여 처리 폼이 나타난다. 대여자는 등록된 사용자 목록에서 드롭다운으로 고른다(로그인 없음). 하단에는 이 물품의 전체 대여 이력이 표로 나열된다.

05 대여 · 반납

목록과 처리 규칙 (/loans)

상태 필터(전체 / 대여중 / 반납완료) 탭으로 조회하며, 각 행에는 연체 여부가 배지로 표시된다.

  • 대여 생성 — 물품 상세 페이지의 폼에서 신청과 동시에 즉시 대여 처리된다. 승인 단계는 없음(1주차 단순화). 재고가 없으면 생성되지 않는다.
  • 반납 처리 — 목록의 "반납 처리" 버튼 클릭 즉시 처리, 승인 절차 없음.
  • 연체일 계산 — 저장되는 값이 아니라 매번 다시 계산되는 파생값이다. 반납 전이면 오늘 − 반납예정일, 반납 후면 반납일 − 반납예정일(음수면 0으로 처리).
06 재고 실사

사람이 대신하는 임시 방식 (/audits)

임시 방식 로봇이 아직 연동되지 않아, 지금은 사람이 직접 실사한 결과를 체크리스트로 입력한다. 이후 Raspbot이 같은 처리 로직(crud.create_audit_session)을 그대로 호출하도록 바꾸면 자동화로 이어진다.

실사 생성 (/audits/new)

  1. 수행자 이름을 입력한다.
  2. 전체 물품이 체크리스트로 나열되고, 실제로 선반에서 확인한 물품만 체크한다.
  3. 제출하면 실사 세션이 생성되고, 체크되지 않은 모든 물품에 대해 "실사 시 미확인" 불일치 기록이 자동으로 남는다.

실사 상세 (/audits/{id})

수행자·일시·확인 건수와, 불일치 목록(물품/위치/비고)을 보여준다. 불일치가 없으면 "모두 확인됐습니다"로 표시된다.

08 업무 규칙 정리

핵심 로직 요약

  • 재고 변동 — 대여 생성 시 available_qty -= 1, 반납 시 available_qty += 1. 이 두 지점 외에는 재고 수치가 바뀌지 않는다.
  • 재고 부족 — available_qty <= 0이면 대여가 생성되지 않는다. 다만 현재 화면에는 실패 사유를 알려주는 안내 문구가 없다 — 다음 개선 포인트.
  • 연체 — 별도 "연체" 상태값이 없다. 상태는 항상 대여중/반납완료 둘 중 하나이고, 연체 여부는 화면에서 매번 계산해 배지로만 보여준다.
  • 실사 불일치 — "전체 물품 집합 − 체크된 물품 집합"으로 정의된다. 즉 실사 대상에서 빠진 물품이 있으면 그 물품도 자동으로 불일치 처리된다는 뜻이니, 실사 시에는 전체 물품을 다 검토해야 한다.
09 API

이후 로봇 연동을 위해 열어둔 JSON 엔드포인트

사람은 화면(HTML)을 쓰고, 아래는 나중에 Raspbot/아두이노가 호출할 것을 대비해 지금 미리 뼈대만 만들어 둔 것이다. 이름은 기술 설계 문서 07번 API 개요와 동일하게 맞췄다.

메서드경로설명
GET/api/items물품 검색 (q/category/location)
POST/api/loans대여 생성, 재고 없으면 400 응답
PATCH/api/loans/{id}/return반납 처리
GET/api/stats/overview대시보드와 동일한 통계 JSON

실사 세션 생성/스캔 API(/api/audit-sessions)와 게이트 API(/api/gate/tap)는 아직 만들지 않았다 — 로봇/아두이노 연동 단계에서 추가한다.

10 실행 방법

로컬에서 띄우기

LabKeeper/web 폴더에서:

  1. pip install -r requirements.txt
  2. uvicorn app.main:app --reload
  3. 브라우저에서 http://127.0.0.1:8000 접속

최초 실행 시 사용자 3명(여해동·김지훈·테스트학생)과 물품 8종이 자동으로 채워진다. DB는 SQLite 파일(labkeeper.db) 하나라 별도 서버 설치가 필요 없다.

11 이번 범위에서 제외한 것

알고 있는 한계

  • 인증 없음 — 로그인 대신 사용자를 드롭다운에서 고르는 방식. 실사용 전에는 로그인/RFID 인증이 필요하다.
  • 승인 절차 없음 — 대여 신청 = 즉시 대여. 관리자 승인 단계는 없다.
  • 실사 자동화 없음 — 사람이 체크리스트로 직접 입력. Raspbot 연동 전까지의 임시 방식이다.
  • 로봇 · 아두이노 연동 없음 — API 뼈대만 준비돼 있고 실제 하드웨어 연동은 다음 단계다.
