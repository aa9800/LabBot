# LabKeeper 실물 안내 경로 안전 기준

> 적용 대상: Raspberry Pi 5 Raspbot 실물 주행  
> 상태: 경로 실행기 미연결, 모터 구동 차단(Fail-Closed)

## 결론

Isaac Sim의 `nav_x`, `nav_y`, `nav_heading`은 가상 장면 좌표다. 현재 실물 라즈봇에는 휠 엔코더, LiDAR, UWB 또는 검증된 Visual SLAM이 없으므로 이 좌표를 실물 바닥 좌표처럼 사용하면 안 된다.

현재 실물 장비가 주행에 사용할 수 있는 입력은 전방 초음파 거리와 바닥 라인 센서다. 이 조합은 충돌 정지와 라인 추종에는 쓸 수 있지만, 임의의 `(x, y)` 위치를 재현성 있게 찾아가는 전역 위치 센서는 아니다.

따라서 `physical_route.status=verified`만 바꾸어도 모터가 켜지지 않는다. `MissionEngine`은 다음 두 조건이 모두 충족될 때만 `navigating` 상태를 허용한다.

1. 경로가 실제 바닥에서 검증되어 `verified` 상태다.
2. 해당 `controller`를 실행하는 실물 경로 실행기가 코드에 명시적으로 등록되어 있다.

둘 중 하나라도 없으면 각각 `awaiting_route_calibration` 또는 `awaiting_route_executor`로 정지한다.

## 현재 분리해야 하는 좌표

| 데이터 | 용도 | 실물 모터 사용 |
|---|---|---|
| `nav_x`, `nav_y`, `nav_heading` | Isaac 장면, 웹 미리보기 | 금지 |
| `shelf_code`, `shelf_row`, `shelf_slot` | 사람에게 선반·단·칸 안내 | 허용 |
| `physical_route.segments` | 향후 실물 전용 체크포인트 경로 | 실행기 검증 전 금지 |

## 실물 주행 방식 선택이 필요한 이유

현재 하드웨어에서 현실적인 1차 방식은 **바닥 라인 네트워크 + 식별 가능한 체크포인트**다. 선반 앞 분기와 정지점마다 QR/AprilTag 같은 시각 표식 또는 별도 바닥 마커를 두고, 라인 센서로 구간을 따라가며 카메라로 현재 체크포인트를 확인하는 구조다.

자유로운 2차원 좌표 주행이 필요하면 휠 엔코더와 위치 보정 수단(예: AprilTag 맵, LiDAR SLAM, UWB)을 추가해야 한다. 초음파 하나로 벽을 피하는 것만으로는 좌표 주행이 되지 않는다.

이 선택은 하드웨어와 경로 표현을 바꾸므로 사용자 승인 없이 임의 구현하지 않는다.

## 현장 검증 순서

1. 로봇을 들 수 있는 작업자와 비상 정지 수단을 준비한다.
2. 주행 구역에서 사람, 의자, 케이블 등 이동 장애물을 치운다.
3. 도크·분기·선반 앞 정지점을 고유 체크포인트로 지정한다.
4. 한 구간씩 최저 속도로 왕복 시험하며 초음파 정지와 라인 이탈 정지를 확인한다.
5. 각 구간을 여러 번 반복해 도착 체크포인트와 정지 오차를 기록한다.
6. 반복 시험을 통과한 구간만 `segments`에 등록한다.
7. 실제 실행기가 해당 경로 컨트롤러 계약을 통과한 뒤에만 컨트롤러를 명시적으로 활성화한다.
8. 선반 경로가 여러 개인 경우 현재 위치에서 다음 선반으로 직접 이어지는 경로도 별도로 검증한다.

## 금지 사항

- Isaac 좌표를 그대로 실물 좌표로 복사하지 않는다.
- 시간 기반 `몇 초 전진/몇 초 회전`만으로 위치를 확정하지 않는다.
- `calibration_required`를 서류상으로만 `verified`로 바꾸지 않는다.
- 검증되지 않은 경로를 일반 순찰 컨트롤러에 대신 넘기지 않는다.
- 사람 감지 결과를 경로 실행기 검증 전에 추적 주행으로 연결하지 않는다.
